# Voice In (Linux / Cross-Platform) - システム要件定義書

**文書バージョン**: 1.0.0  
**作成日**: 2026-09-04  
**ステータス**: 正式承認版  
**対象システム**: Voice In (Python / PyQt6 / Rust core)

---

## 1. システム概要と目的

### 1.1 目的
Voice In は、Linux（Ubuntu, Fedora, Arch 等）をはじめとするデスクトップ環境において、キーの長押し操作（Hold-to-Talk）だけでアクティブなあらゆるアプリケーション（VSCode, ブラウザ, Slack, ターミナル等）に高精度な音声入力・自動文章整形・自動貼付を提供するクロスプラットフォーム音声入力アシスタントである。

### 1.2 背景と課題
- **Linux デスクトップにおける音声入力環境の不足**: Windows や macOS に比べ、Linux 環境では実用に耐える日本語音声入力ツールが極めて乏しかった。
- **X11 / Wayland の入力制約**: ウィンドウフォーカス制御やグローバルショートカット、テキスト貼り付けの挙動がディスプレイスピードやデスクトップ環境（GNOME, KDE 等）によって異なり、安定した動作が困難だった。
- **低遅延かつ安定した音声録音**: Python の標準オーディオライブラリ（PyAudio など）は環境依存のクラッシュやオーバーヘッドが大きかったため、**Rust (`cpal`) によるネイティブ音声処理コア** を採用し、極限の低遅延と堅牢性を両立させた。

## 2. システム構成と対象環境

| 項目 | 要件仕様 |
| :--- | :--- |
| **対応OS** | Linux (Ubuntu 20.04+, Fedora, Debian, Arch等), Windows 10/11, macOS |
| **ディスプレイサーバー** | X11 (完全対応 / xdotool利用), Wayland (基本動作対応) |
| **ランタイム** | Python 3.10 以上, Rust (コンパイル時 / Maturin) |
| **GUIフレームワーク** | PyQt6 (Qt 6.x) |
| **オーディオバックエンド** | Rust `cpal` + `hound` (PyO3 による Python バインディング) |

## 3. 機能要件 (Functional Requirements)

| 要件ID | 大項目 | 機能名 | 詳細仕様 |
| :--- | :--- | :--- | :--- |
| **FR-001** | 入力制御 | グローバルホットキー | `pynput` を使用し、指定キー（デフォルト: `Left Alt`、変更可能: `Right Alt`, `Left Ctrl`, `Right Ctrl`）の長押しで録音を開始し、離脱で停止する。 |
| **FR-002** | 音声処理 | Rust ネイティブ録音 | Rust `cpal` によるハードウェア直結の 44.1kHz PCM 録音。バッファリングと WAV 書き出しを Rust 側で安全に実行。 |
| **FR-003** | 音声処理 | Rust ネイティブ VAD | 録音完了時に Rust 側で RMS エネルギーとピーク値を計算し、設定された閾値未満（無音・誤タッチ）の場合は即座にキャンセル。 |
| **FR-004** | AI連携 | Google Gemini | `google-genai` SDK を使用。WAV 音声をバイナリ直接送信し、長文やプログラミング用語を精密に文字起こし・整形。 |
| **FR-005** | AI連携 | Groq Cloud | `groq` SDK を使用。Whisper Large v3 による超高速文字起こし後、LLaMA 3.3 70B で文章整形を行う2段階パイプライン。 |
| **FR-006** | AI連携 | Local Whisper | `faster-whisper` を使用。オフライン・完全プライベート環境でのローカル推論に対応（CUDA / CPU）。モデルダウンロード UI を完備。 |
| **FR-007** | 文脈最適化 | コンテキスト認識 | アクティブウィンドウ（`xdotool getactivewindow` / Win32）のタイトル・プロセスから `DEV`, `BIZ`, `DOC`, `STD` を自動判別し、最適プロンプトを注入。 |
| **FR-008** | テキスト処理 | 辞書強制置換 | ユーザー定義辞書（`dictionary`）に基づき、AI整形後の特定語句を確定前に置換。 |
| **FR-009** | 入力注入 | 自動貼り付け (Auto Paste) | クリップボード格納後、Linux では `xdotool`、Windows では `pynput` を用いて、修飾キーを解除した状態で `Ctrl+V` をアクティブウィンドウへ自動送出。 |
| **FR-010** | UI | フローティングオーバーレイ | PyQt6 による透過・丸型オーバーレイ (`AquaOverlay`)。ドラッグ移動・座標保存、録音中パルスアニメーション、ステータス表示（待機/録音/処理中/成功/エラー）。 |
| **FR-011** | UI | システムトレイ常駐 | `QSystemTrayIcon` による常駐。アイコン動的生成、プロバイダ即時切替、設定・履歴・セットアップウィザードの起動。 |
| **FR-012** | 初期導入 | セットアップウィザード | 初回起動時に自動起動。言語選択、AIプロバイダ＆APIキー入力、マイクテスト、LocalモデルDLを段階的にガイド。 |

## 4. 非機能要件 (Non-Functional Requirements)

### 4.1 性能・リアルタイム性
- **録音レイテンシ**: Rust ネイティブバッファリングにより、キー押下から音声フレーム取得開始まで 5ms 未満。
- **API 応答性**: Groq 使用時、発話終了から自動入力完了まで約 0.8〜1.5 秒の超高速レスポンス。

### 4.2 安定性・堅牢性
- **GIL 回避と非同期ワーカー**: AI 推論および外部 API 通信は `QThread` (`AIWorker`) で実行し、Qt メインスレッド（GUI / アニメーション）のフリーズを完全防止。
- **シグナルハンドリング**: `SIGINT` (Ctrl+C) を適切にトラップし、トレイアイコンやフックを安全に解放してクリーン終了。

### 4.3 プライバシー・セキュリティ
- **オフライン対応**: 機密データを外部クラウドに送信できない環境向けに、ローカル GPU/CPU 完結の `Local Whisper` モードを提供。
- **一時ファイル消去**: 一時録音 WAV ファイルは推論完了直後にバックグラウンドスレッドで即座に物理削除。
